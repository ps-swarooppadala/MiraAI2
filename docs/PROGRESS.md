- **Dynamic camera zoom fix #2: runaway zoom-in that never came back out, plus added pan.** The user ran both routines again after the preview-scale fix above and reported the camera "keeps zooming in... even when I zoom out" (i.e. step back), and asked that it also pan toward wherever the skeleton actually is, not just zoom symmetrically about a fixed center.

  **Root cause — a real control-loop bug, not a tuning issue.** `FramingZoomController`'s bounding box is always measured against the raw, un-zoomed sensor frame (applying more zoom to the *display* doesn't change what a landmark's normalized position reads as — confirmed by the previous fix's own reasoning). The old formula, `desiredRatio = currentZoomRatio * (target / coverage)`, treated `coverage` as if it already reflected the currently-applied zoom. Since it never does, every tick multiplied the ratio by the same factor again — for a person standing still, this compounds every frame with no equilibrium, until it pins at `MAX_ZOOM_RATIO` (3.0) and has no way back down even as the person moves further away (which only makes the runaway math want to climb even more, immediately re-pinning at the max).

  **Fixed.** `tick()` now computes an absolute `desiredZoom = target / coverage` fresh from the raw frame each call (independent of the ratio already applied) and steps the current ratio *toward* that fixed target, so it settles once reached instead of compounding — this is the actual bug fix.
